# Technical Specifications: Bump Vitest and Vitest UI to v4.1.2

## Files Changed

- `package.json` — bumped `vitest` and `@vitest/ui` from `^4.0.18` to `^4.1.2`, aligning
  both with the already-bumped `@vitest/coverage-v8@^4.1.2`.
- `package-lock.json` — regenerated by `npm install` to record the resolved `4.1.2` install
  tree for `vitest` and `@vitest/ui`.

## Decisions

- Ran `npm install vitest@4.1.2 @vitest/ui@4.1.2` rather than hand-editing the version
  ranges, so npm resolves and locks the exact dependency tree itself rather than risking a
  manually-typed range drifting from what actually gets installed (security-guidelines.md
  rule 1).
- No other file was touched: the resolved `vitest`/`@vitest/ui` entries in
  `package-lock.json` were already at `4.1.2` under the prior `^4.0.18` range (npm had
  already resolved to the latest matching `4.x` release), so only the declared version
  ranges needed updating — no transitive dependency changes, no config changes required to
  keep the suite passing.
- `npm install` reported pre-existing peer-dependency warnings (`vite-hot-client` vs.
  `vite@8.0.3`) and `npm audit` findings unrelated to this bump; left untouched as out of
  scope per `business-specifications.md`.
